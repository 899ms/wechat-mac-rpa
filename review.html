🔍 项目问题 Review（校正版）

重新用代码逐条验证后，筛掉了误判项。以下是我确认有问题的代码 bug，请勾选你要修的。

P1 _is_fuzzy_duplicate 未处理 video 类型
video 不在 ("image", "sticker", "mixed") 中，模糊去重走 text 分支，text 为空直接返回 False。 _msg_id 已用 image_description 做精确指纹（已修复），但如果 API 对同一视频的两个 tick 给出略有差异的 image_description（如"长发女性"vs"一个女性"）， 精确去重不同 + 模糊去重失效 → 同一视频被重复存储。
if msg.message_type in ("image", "sticker", "mixed"): # ← video 没在里面
影响：同一视频重复入历史，上下文膨胀。
P1 link_card 的 _msg_id 和空 text 消息冲突
_msg_id media 分支只有 image/sticker/mixed/video，link_card 走 else 分支用 msg.text。 API 返回的 link_card 通常 text=""（文字放在 image_text 里），所以 content = ""。 同一个 sender 发的两条不同 link_card，或一条 link_card 和一条 video，text 都为空时，_msg_id 完全相同，后一条被去重过滤。
content = msg.text # link_card 走这里，text 通常为空
影响：不同的 link_card 被误判为重复，漏读消息。
P2 群聊 sender 校验逻辑存在误判（概率极低）
sender == text and len(text) > 3 时，认为 API 把消息内容错当成了 sender，用 last_left_sender 替代。 如果群聊中有人昵称等于消息内容（比如昵称"张三今天来了"发了"张三今天来了"），会被错误替换为上一个发言者。
if sender == text and len(text) > 3: sender = last_left_sender
影响：极特定场景下消息被错误归因，概率极低。
P2 no_reply_chats 免回复列表严重不足
当前只有 {"腾讯新闻", "文件传输助手"}，缺少微信支付、微信团队、订阅号、各种服务号通知等。 这些账号的消息会被当成普通聊天处理，可能触发无效回复。
self.no_reply_chats = {"腾讯新闻", "文件传输助手"}
影响：Bot 可能对服务号/系统通知回复无意义内容。属于配置缺失，非代码 bug。
